# 10. Миграция на Cassandra: модель данных, стратегии репликации и шардирования

## 10.1
- Cassandra относится к AP по CAP-теореме (доступность и устойчивость к разделению)
  
- критически важные с точки зрения целостности и скорости обработки:
  - товары, обновление остатков
    - частый поиск 
    - частое обновление остатков
  - история заказов
    - большой объем историй заказов
  - создание и обновление корзины
    - необходимо быстрое создание и обновлние корзины, необходимо обеспечить высокое чтение
    - данные должны быть доступны при отказе узла 
    
## 10.2
- товары
```
create table product {
   product_id uuid,
   title text,
   category text,
   price int,
   geo_zone text,
   quantity int,
   PRIMARY KEY((category, geo_zone), price, product_id)
}

где 
    - category, geo_zone - распределение по нодам
    - price, product_id - поиск, сортировка внутри партиции
```

- заказы
```
create table order {
   order_id uuid,
   user_id uuid,
   date_order TIMESTAMP,
   status text,
   total_amount int,
   geo_zone text,
   quantity int,
   price int,
   PRIMARY KEY(user_id, order_id))
}

где 
    - user_id - все заказы пользователя в одной партиции
    - order_id - поиск, сортировка внутри партиции
```

- корзина
```
create table cart {
   cart_id uuid,
   session_id uuid,
   items MAP<UUID, INT>,
   status text,
   total_amount int,
   created_at TIMESTAMP,
   updated_at TIMESTAMP,
   expires_at TIMESTAMP,
   product_id text,
   quantity int,
   PRIMARY KEY(user_id, session_id)
}

где 
    - user_id - корзина пользователя в одной партиции -> быстрый доступ
    - session_id - хранение нескольких корзин
```

## 10.3
| Стратегия            | Краткое описание                                                | Сущности                  | Обоснование                                                                                             |
|----------------------|-----------------------------------------------------------------|---------------------------|---------------------------------------------------------------------------------------------------------|
| Hinted Handoff       | Передача с подсказкой (hint - инфо о пропущенной записи)        | продукты, истории заказов | Учитываем, что данные могут расходится в какой-то момент времени                                        |
| Read Repair          | восстановление согласованности при чтении                       | корзина                   | Корзина должна быть максимальна актуальной, поэтому восстанавливаем (если необходимо) при чтении данные |
| Anti-Entropy Repair  | процесс сравнения и синхронизации реплик (полная синхронизация) | продукты, заказы          | Периодически необходимо делать синхронизацию, но так как объем большой делаем в фоновое время           |
